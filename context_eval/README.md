## Context Window Management Evaluation

The `context_eval/` module evaluates four context-window management strategies under the same long-context workload:

* Sliding Window
* Observation / Tool-Output Masking
* Recursive Summarization
* Zone-Based Pruning

The goal was to determine which strategy provides the best practical trade-off between **task accuracy, token consumption, and latency** for the Copperleaf agent.

### Evaluation Setup

Each strategy was evaluated against the same long-context test suite containing multi-turn, tool-heavy conversations where important information can become buried under subsequent tool outputs.

The evaluation script (`evaluate.py`) runs each strategy and records:

* **Accuracy** — whether the agent successfully answered the task after context pruning.
* **Average input tokens** — average number of tokens sent to the model.
* **Average output tokens** — average number of tokens generated by the model.
* **Average latency** — average response time in seconds.

This ensures that the strategies are compared under the same workload rather than being evaluated independently.

## Results Analysis

### Sliding Window

Sliding Window had the **lowest latency** at 4.504 seconds and the lowest average output-token usage.

However, it achieved only **80% accuracy (8/10)**.

The strategy keeps only the most recent turns, which can remove important information from earlier parts of a long conversation. In this evaluation, this caused two test cases to fail.

**Result:** Fast, but less reliable for long-context conversations.

### Observation / Tool-Output Masking

Observation Masking achieved **100% accuracy (10/10)** while reducing the average input context from 9,978 tokens to 7,930 tokens compared with Sliding Window.

It also had substantially lower latency than the two summarization-based approaches.

The strategy removes or limits large tool outputs while preserving conversational information, making it particularly effective for the tool-heavy workload used in this evaluation.

**Result:** Strong balance between accuracy, token reduction, and latency.

### Recursive Summarization

Recursive Summarization achieved **100% accuracy** and reduced average input tokens dramatically to only **303 tokens**.

However, this came with a significant latency cost: **14.991 seconds**, the highest latency among the four strategies.

The additional summarization step introduces extra model processing, which makes the strategy considerably slower despite its excellent context compression.

**Result:** Excellent token reduction and accuracy, but expensive in latency.

### Zone-Based Pruning

Zone-Based Pruning also achieved **100% accuracy** and produced the smallest average input context at **219 tokens**.

Its average latency was **14.434 seconds**, which is almost as high as Recursive Summarization.

Although it achieved the lowest input-token usage, it generated the highest average output-token count at **617 tokens**.

**Result:** Excellent context compression, but the latency and output-token costs reduce its practical advantage.

---

## Production Decision

Based on the measured results, **Observation / Tool-Output Masking** is the selected strategy for the production system.

The decision is based on the evaluation results rather than theoretical preference.

Observation Masking was the only strategy that combined:

* **100% task accuracy**
* Significant reduction in input tokens
* Much lower latency than the summarization-based strategies
* A simpler pruning approach without requiring recursive summarization

The other strategies each have a specific advantage:

* **Sliding Window** is the fastest, but loses accuracy.
* **Recursive Summarization** achieves excellent compression, but has the highest latency.
* **Zone-Based Pruning** achieves the smallest input context, but also has high latency and higher output-token usage.

Therefore, Observation Masking provides the best overall trade-off for Copperleaf's tool-heavy agent workload.

## Reproducing the Evaluation

Run the evaluation from the project root:

```bash
python -m context_eval.evaluate
```

The script runs all four strategies against the shared test suite and produces the metrics used in the comparison above.
